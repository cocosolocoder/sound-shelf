# SoundShelf

音频曲目与播放清单。

需要Python 3.10 或更新版本，包含标准库 sqlite3。

查看命令帮助：

```sh
python3 app.py --help
```

启动本地服务：

```sh
python3 app.py serve --host 127.0.0.1 --port 8080 --data-dir data
```

打开 http://127.0.0.1:8080 查看首页。Ctrl+C 停止服务。`--data-dir` 指定本地业务数据目录，重启时继续使用同一目录。

接口：

- `GET /health` 返回服务状态和产品名称。
- `GET /api/tracks` 返回曲目列表，首次启动时为空，按 `id` 升序。
- `POST /api/tracks` 手动收录曲目，使用 JSON 提交资料：

  | 字段 | 类型 | 说明 |
  | --- | --- | --- |
  | `title` | 字符串 | 名称，必填，去掉首尾空白后不能为空；内部文字、空格与换行按原文保留，允许写成多行 |
  | `source` | 字符串 | 来源，必填，网址或本地文件路径等文字；不检查是否可播放，也不合并不同写法 |
  | `duration` | 数字或省略 | 时长（秒），省略或为 `null` 表示未知；必须是有限的非负数，允许 `0` 和小数 |
  | `cover_url` | 字符串 | 封面地址，可留空，不检查远端文件 |
  | `description` | 字符串 | 说明，可空，保留换行 |
  | `tags` | 字符串数组 | 标签，可为空数组或省略；各项去掉首尾空白、忽略空项并按首次出现顺序去重 |
  | `save_as_new_version` | 布尔值 | 同一来源已存在时，设为 `true` 才新增独立标识的新版本 |

  成功（含另存新版本）返回 `201` 和完整记录；来源重复且未明确另存时返回 `409`，
  响应中的 `existing` 列出该来源已有记录的 `id` 和 `title`；无效 JSON、字段类型错误
  或字段值不合法返回 `400` 且不写入数据。
  标签项的内部文字按原文保存，允许包含换行以及中英文逗号、顿号等标点，
  这些字符不会被当作标签之间的分隔；只有两个标签项的完整文字相同时才去重。
- `PATCH /api/tracks/{id}` 编辑已有曲目，使用 JSON 对象提交需要修改的资料字段：

  | 字段 | 类型 | 说明 |
  | --- | --- | --- |
  | `title` | 字符串 | 名称，去掉首尾空白后不能为空；内部文字、空格与换行按原文保留，允许写成多行 |
  | `source` | 字符串 | 来源，去掉首尾空白后不能为空；已有来源的记录不能清空 |
  | `duration` | 数字或 `null` | 时长（秒），`null` 表示未知；必须是有限的非负数，允许 `0` 和小数 |
  | `cover_url` | 字符串 | 封面地址，可留空 |
  | `description` | 字符串 | 说明，可空，保留换行 |
  | `tags` | 字符串数组 | 标签，可为空数组；各项去掉首尾空白、忽略空项并按首次出现顺序去重 |

  只修改明确提交的字段，省略的字段保留旧值；成功返回 `200` 和修改后的完整曲目。
  无效 JSON、非对象请求或任一资料字段不合法返回 `400` 且整条记录保持原样，
  字段错误的响应中 `field` 指出对应字段。来源未改变时即使有多个版本使用同一来源
  也允许修改其他资料；来源改成其他曲目已使用的文字时返回 `409`，响应中的
  `existing` 列出冲突记录的 `id` 和 `title`，此时不会覆盖、合并或自动另存版本。
  编辑不存在的标识返回 `404`。
- 首页 `GET /` 提供同样规则的手动收录表单，提交成功后立即在列表中显示新曲目。
- 首页曲目列表上方有关键词查找（`GET /?q=关键词`）：在名称、来源、说明与每个标签
  的完整文字里查找连续文字，任一项包含关键词即显示该曲目；不要求同时命中多项，
  也不会把多个字段或多个标签拼起来凑一次命中。封面地址与时长不参加搜索。
  关键词去掉首尾空白后使用，内部空格与标点（含 `%`、`_`、引号、尖括号）均按普通
  文字查找，不作为通配或标记符号；中文按原文字匹配，英文字母不区分大小写。
  结果沿用现有列表的资料展示与编辑入口，按曲目标识升序排列，并显示命中数量与
  曲库总数；名称相同的记录、同一来源另存的多个版本各自独立参加搜索，不做合并。
  只有名称的旧记录也可按名称找到；缺失来源、空说明和空标签视为没有可匹配的文字，
  “未填写”“无”等页面占位提示不参加搜索。关键词留空或只含空白等同于不筛选，
  清除搜索后恢复完整列表与原有顺序；没有匹配结果时提示“没有符合关键词的曲目”
  并保留搜索条件，曲库本来为空时仍提示尚未收录曲目。搜索条件随网址保留，重新打开
  同一地址看到同样条件下的当前结果；搜索只改变首页展示，不新增或改写曲目，
  `GET /api/tracks` 仍返回全部记录。
- 首页列表中的每条曲目都有“编辑”链接，进入 `GET /tracks/{id}/edit` 看到当前资料并修改；
  保存成功后回到列表，原记录标识不变，列表立即显示修改结果。取消则回到列表，不保存改动。
  旧记录（只有标识与名称）也能编辑，未填写来源时继续保留缺失状态，不参加来源重复判断。
  名称框是多行输入框：接口收录的名称即使含有换行（例如第一行“夜航”、第二行为空、
  第三行“现场  版”），打开编辑页后中文、内部空格、连续空行与各行文字仍出现在原有
  位置，不会被并成“夜航现场  版”；名称中的引号、尖括号以及看起来像网页标签的内容
  一律按普通文字转义显示，不会变成页面元素。首页曲目列表中的名称也按原有分行显示。
  不碰名称框、只修改时长、说明等其他合法资料时，保存不会改写名称原文：提交文字在
  统一换行（CRLF/CR 归一为 LF）并去掉首尾空白后与原名称相同即视为未修改，原名称
  逐字节保留——原本使用 LF、CRLF 或 CR 的换行写法都不因网页显示与表单提交的写法
  差异被改写，仅内部换行写法不同的两段名称仍各自保留；仅在名称首尾增删空白沿用
  现有裁剪规则，不算改动内部内容。确实修改名称内部的文字、空格或分行时，按本次
  填写保存（只去掉整段首尾空白，内部空行与空格保留，网页此次修改的换行统一为 LF）；
  保存成功后更新原曲目并返回列表，再次打开编辑页与曲目列表接口读到的名称都与保存
  结果一致。名称删空或只剩空格、制表符、换行时返回 400 并在名称旁指出错误，整条
  曲目不保存任何修改；名称合法但时长等其他资料不合法导致保存失败时同样返回 400 且
  不写入资料，页面完整保留本次填写的多行名称与其他资料（不被旧值替换、不失去分行），
  只修正出错字段后再保存即采用错误页中保留的名称。首页收录表单的名称框同样支持多行。
  来源框完整呈现已保存来源的内部文字、空格与分行（来源按文字保存，只忽略首尾空白，
  内部换行也是来源的一部分）。不碰来源框、只修改名称等其他资料时，保存不会改写来源
  原文：提交文字在统一换行（CRLF/CR 归一为 LF）并去掉首尾空白后与原来源相同即视为
  未修改，原来源逐字节保留——原本使用 LF、CRLF 或 CR 的换行写法都不因网页显示与表单
  提交的写法差异被改写，仅内部换行写法不同的两段来源仍各自保留、不会被合并，其他版本
  共用同一来源时这种保存也照常成功。确实修改来源内部的文字、空格或分行时，按本次填写
  去掉首尾空白后保存（内部换行统一为 LF）；新来源与其他曲目保存的来源完整文字相同时
  仍拒绝保存并显示实际占用者，名称相同或仅在内部空格、大小写上不同不算冲突。已有来源
  不能清空。时长等其他资料不合法或来源冲突导致保存失败时，整条曲目保持原样，页面保留
  本次填写的完整来源与其他资料；只修正出错内容后继续保存，未改来源仍保留原文，确实
  改过的来源则采用回填内容。
  封面地址框是多行输入框，封面地址按一段文字维护（不拆成多个地址，也不根据网址
  格式替用户改写）：接口收录的地址中的中文、内部空格、连续空行与各行文字打开编辑页后
  仍完整出现在原有位置，引号、尖括号与看起来像网页标签的内容一律按普通文字转义显示，
  不会变成页面元素。不碰地址框、只修改名称或时长等其他合法资料时，保存不会改写地址原文：
  提交文字在统一换行（CRLF/CR 归一为 LF）并去掉首尾空白后与原地址相同即视为未修改，
  原地址逐字节保留——原本使用 LF、CRLF 或 CR 的换行写法都不因网页显示与表单提交的写法
  差异被改写，仅给地址首尾增删空白也不算改动内部内容。确实修改地址内部的文字、空格或
  分行时，按本次填写保存（只去掉整段首尾空白，内部空行与空格保留，网页此次修改的换行
  统一为 LF）；主动删空或只留下空白则保存为空字符串，不要求补填；原本没有封面地址的
  曲目也可以正常补填或继续留空。保存仍更新原来的曲目标识，重新打开编辑页与曲目列表
  接口读到的封面地址与保存结果一致。时长等其他资料不合法或来源冲突导致保存失败时整条
  记录不保存，错误页完整回填本次填写的封面地址（不换回旧值、不丢分行）；只修正出错
  资料再保存，未改动的地址仍保留原文，确实改过的地址则保存回填内容。直接通过 JSON
  接口收录和编辑封面地址的规则保持兼容：只裁整段首尾空白，接口提交的内部换行写法
  逐字节保留，不新增远端文件检查或可播放性检查。
  说明框完整还原已保存说明的原文：开头空行、段落之间的空行、结尾空行以及首尾空格都在
  相同的行与位置（HTML 解析会吞掉说明框起始标签后的第一个换行，页面渲染时已补回）；
  说明中的中文、引号、尖括号以及看起来像网页标签的内容一律按普通文字转义显示。
  不碰说明框、只修改名称等其他合法资料时，保存不会改写说明原文：提交文字在统一换行
  （CRLF/CR 归一为 LF）后与原说明相同即视为未修改，原说明逐字节保留，原本使用 LF 或
  CRLF 的换行写法、首尾空白都不变，空字符串与只有空行或空格的说明也各自保留、不会互相
  替换。确实修改说明时按本次填写的文字与空行保存（换行统一为 LF）；主动删空说明保存为
  空字符串；其他字段（如时长）不合法导致保存失败时整条记录保持原样，页面重新显示本次
  填写的说明（包括开头空行），只修正出错字段后继续保存即保存回填的说明。
  编辑页的标签每个标签项一个输入框：一个标签可以在自己的框内换行写成多行，
  接口收录的标签即使含有换行，打开编辑页后直接保存也不会被拆开；标签文字里的
  中英文逗号、顿号等标点同样原样保留，不会被当作标签之间的分隔。修改某个框
  只影响该标签，增加一个框即新增标签，删除某个框即删除该标签，其余标签的先后
  关系保持不变；即使另有一个标签的某一行与多行标签中的一行文字相同，两者仍是
  各自独立的标签，不会被合并或删除。框内文字与内部空行没有变化、或仅给整项
  首尾增加空白的项，保存时保留该项原来的完整文字，包括原文使用的 LF、CRLF
  或 CR 换行写法——浏览器显示与提交换行的写法差异不算修改；仅换行写法不同的
  两项标签仍是各自独立的两项，直接保存或只改名称不会被合并，删除其中一项时
  另一项也保留自己的原文。确实修改某项文字或内部空行时，该项按本次填写保存
  （换行统一为 LF），其余未修改项仍保留原文。全部删空则保存为空数组；每项
  去掉首尾空白、忽略空项，去重以最终要保存的完整文字为准，完全相同的项只保留
  第一次出现。
  保存时若其他字段（如时长、来源）不合法，整条记录保持原样，页面重新显示时
  本次填写的各项标签（含项内换行与项之间的边界）也会逐框保留，便于修正后继续保存。
- 未知路径返回 404，已知路径不支持的方法返回 405。

```sh
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/api/tracks
curl -X POST http://127.0.0.1:8080/api/tracks \
  -H 'Content-Type: application/json' \
  -d '{"title":"夜航","source":"/music/yehang.flac","duration":243.5,"tags":["民谣","现场","民谣"]}'
curl -X PATCH http://127.0.0.1:8080/api/tracks/1 \
  -H 'Content-Type: application/json' \
  -d '{"title":"夜航（新版）","duration":300}'
```

重复收录按去掉首尾空白后的 `source` 文字判断（不按名称）。同名但来源不同的曲目可直接收录；
同一来源的多个版本都会出现在列表中。只有标识与名称的旧记录会被原样保留，缺少的资料显示为
未填写，且不会被当作任何来源的重复项。
